01 / Research question

What makes a useful
agent intervention?

A coding agent has to inspect a repository, edit files, test its changes, and decide when to submit a patch. Each action consumes a limited budget. Improving a local measurement only matters if the complete run produces a correct repair.

I investigated two interventions: reallocating the agent’s inference time and editing its submission decisions with LoRA. The work combines runtime analysis, a memory-efficient editing implementation, controlled evaluation tasks, and paired comparisons of complete trajectories.

Central finding

An edit can preserve most ordinary-token outputs while changing when an agent submits and whether it stops afterward. Those properties need separate measurements, followed by repair tests.

02 / Completed study

Allocating a fixed
inference budget.

I fitted a time model using agent steps and generated tokens, then checked its transfer by holding out entire repositories. Across 78 runs, the combined model had a mean absolute timing error of 13.5 seconds, compared with 28.2 seconds for tokens alone. These estimates use the steps and tokens observed in a run; they do not predict an unknown future trajectory.

I then varied thinking budgets, tool-call limits, and model-turn limits. One configuration removed timeouts on an eight-issue local comparison while retaining three repairs, but its public competition score fell from 0.15 to 0.08. Timing estimates also transferred poorly when thinking mode changed.

The result identifies a practical evaluation requirement: measure both resource use and repair quality, and recalibrate the cost model when the execution mode changes.

03 / Method development

Editing a 31B model
with limited GPU memory.

I captured intermediate representations one decoder layer at a time, keeping hidden states on CPU. This allowed the editing procedure to use a single RTX 5060 with 8 GB of GPU memory, without placing the full model on that GPU.

With one LoRA factor fixed, I derived and implemented a closed-form refit of the other. A regularized quadratic objective balances retaining the edit at 60 decision positions against suppressing its effect at 18,927 ordinary positions.

  1. Formulate the optimization Differentiate the objective with respect to the matrix factor and solve its stationary condition. Check the positive-definite Hessian conditions that establish a unique global minimum.
  2. Reuse the expensive computation Cache an eigendecomposition and use the Woodbury identity to exploit the small number of decision rows during refitting.
  3. Measure effects beyond the fitting objective Compare intended submission decisions, false submissions, ordinary-token agreement, termination, and actual repairs.

The refit reached 98.97% agreement with the base model on the ordinary-token evaluation, yet false submissions increased from 1 of 38 to 14 of 38 serving-probe cases. Preserving token choices did not preserve the agent’s use of actions.

04 / Completed prospective replication

Test the behavior.
Then grade the repair.

I tested the frozen edit on 36 fresh issues from SymPy, Sphinx, xarray, pylint, and pytest. These repositories were excluded from edit development. Task selection, execution order, code and weight hashes, and the primary hypothesis were recorded before the first inference run.

Four conditions separate the model edit from a submission guard: original or refitted weights, each with the guard off or on. The 144 main executions were supplemented by eight repeat runs on four preselected issues. Each run used a 300-second limit, 80 counted tool calls, and 80 model turns.

Without the guard, the pre-specified submission signature—an empty first submission or at least three generated submission calls—occurred in 13 of 36 refit runs and none of the paired base runs. The exact paired test gave p = 0.000244. The base model nevertheless reached its time limit in 33 of 36 runs; the absence of that signature does not imply good termination.

Repair grading used the official Evaluator on Kaggle, with passing gold-patch and failing empty-patch controls. The study reproduced the submission anomaly in a different runtime and scaffold, but did not establish improved repair performance. Its scope is the same 31B model and frozen edit, not a demonstration across model families.

Reproducibility

The submission includes task definitions, predictions, traces, grading logs, and executable analyses. A hosted CPU notebook completed 148 analysis checks. Reproducing those analyses is separate from rerunning 31B inference.

05 / Updated November 11, 2026

Research status
and next questions.

The report has been submitted, and the 152-run replication and its repair grading are complete. DOI creation has been requested. The report was submitted to the Gemma 4 Developer Agent Paper competition on November 11, 2026.

The continuing research direction is to understand which measurements reveal an agent’s behavior before deployment. Follow-up questions include:

  • Whether explicitly training against false submissions and testing post-submission states can improve action specificity without sacrificing correct repairs.
  • Whether the same failure pattern appears in other models and execution environments.
  • How to recalibrate resource budgets across reasoning modes while preserving repair quality.

These are open questions, not completed findings. My contribution so far spans mathematical derivation, low-memory implementation, experimental controls, paired statistical analysis, and reporting both successful and unsuccessful interventions.
